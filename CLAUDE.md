# postmarketOS на Xiaomi POCO X3 Pro (vayu)

Установка и доводка postmarketOS с Phosh на POCO X3 Pro, плюс патчи, без которых
устройство не работает. Подробности — в `README.md` (на английском, для внешнего читателя)
и `TZ-pmos-vayu.md` (на русском, полный разбор).

Локальные адреса, пути и учётные данные — в `CLAUDE.local.md`, он не коммитится.

## Устройство

Xiaomi POCO X3 Pro, `vayu_global`, модель M2102J20SG, **панель Huaxing** (`huaxing,nt36672`).
Ядро `7.0.0-sm8150` из ветки `sm8150/7.0-wip`, postmarketOS edge, systemd, Phosh,
шифрование диска включено.

Панель определяется без root прямо из pmOS:

```sh
sudo dmesg | grep -o 'msm_drm.dsi_display0=[^ ]*'
# dsi_j20s_42_02_0b_video_display -> Huaxing
# dsi_j20s_36_02_0a_video_display -> Tianma
```

## Чего нельзя делать

**Вернуться в fastboot программно невозможно.** Проверены `reboot bootloader`,
`systemctl reboot`, `reboot -f` из initramfs и запись `bootonce-bootloader` в раздел
`misc` — все вешают устройство. Только кнопками: Power 10–15 с, затем Vol Down + Power.
Значит любая перепрошивка требует человека, и планировать её надо соответственно.

**Не собирать образ без `--zap` при смене режима шифрования.** pmbootstrap переиспользует
rootfs-chroot от прошлой сборки, `postmarketos-base-nofde` остаётся, и initramfs выходит
без поддержки LUKS.

**Не судить о состоянии загрузчика по свойствам Android.** На xiaomi.eu они подделаны.
Правду говорит только `fastboot getvar unlocked`.

## Что важно помнить

- **Первая загрузка занимает до 8 минут.** Не объявлять сборку неудачной раньше десяти.
- `pmbootstrap build` без `--arch aarch64` собирает под архитектуру сервера. Для ядра это
  не проблема (там `pmb:cross-native`), для остальных пакетов — проблема.
- Сборка падает на `Zapping buildroots` с `umount ... exit code 32` — лечится
  `pmbootstrap shutdown`. Делать перед каждым запуском.
- Сообщение `Firewall is enabled, but will not work` в конце `pmbootstrap install`
  ложное: функция только печатает. Проверять через `nft list ruleset` на устройстве.
- Имя USB-сетевого интерфейса непредсказуемо (`enp4s0f4u1`, не `usb0`). Искать по
  исключению, не по шаблону `usb*`.
- Часы после установки могут стоять на десятилетия вперёд, из-за чего DNSSEC отвергает
  все ответы и DNS выглядит сломанным. Само не чинится: NTP нужен DNS.

## Известные проблемы

**GPU сбрасывается.** Блок CCU читает неотображённую память, срабатывает hangcheck, ядро
сбрасывает GPU, текстуры гибнут. Это баг Mesa/freedreno или msm, не наш.

Смягчено двумя способами, оба применены:

- патч в `phoc` (`patches/upstreamable/0003-*`) — сессия переживает сброс вместо падения;
- `FD_MESA_DEBUG=sysmem` через `~/.phoshdebug` — частота сбросов падает примерно на
  порядок. **Этот файл не переживёт перепрошивку rootfs**, при пересборке образа переменную
  надо вносить заново.

**Flathub недоступен** с домашней сети — TLS-соединение рвётся. Софт ставить через `apk`.

**Сотовая связь не работает** и не проверялась — отдельная задача в issue #1.

## Патчи

`patches/upstreamable/` — три штуки, все самодостаточные и не завязанные на WIP-ветку
ядра. Первые два в pmaports, третий в phoc. `patches/local/` — привязка ядра к снапшоту
WIP-ветки, в upstream не пойдёт.

При правке пакетов: изменённые файлы лежат в `pmaports/`, раскладываются скриптом
`scripts/apply.sh`, дальше `scripts/build.sh` и `scripts/flash.sh`.
